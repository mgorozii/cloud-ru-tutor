### Ключевые особенности архитектуры
4-слойная архитектура: UI → Services → Data → External

Модульность: независимые сервисы для каждой задачи

Гибкость LLM: выбор между облачным (Gemini) и локальным (Qwen) провайдером

Векторный поиск: ChromaDB с HNSW индексом (косинусное расстояние)

Разделение данных: SQLite для чанков, ChromaDB для эмбеддингов

### Структура данных
Document (исходный документ)
url (string) — ссылка на источник

title (string) — название документа

text (string) — текстовое содержимое

Chunk (фрагмент документа)
id (string) — уникальный идентификатор

source_url (string) — ссылка на исходный документ

source_title (string) — название документа

chunk_index (int) — порядковый номер чанка

text (string) — текст чанка (850 символов, overlap 140)

ChromaVector (векторное представление)
id (string) — идентификатор чанка

embedding (float) — векторное представление (rubert-tiny2)

metadata (json) — метаданные (url, title, chunk_index)

# Связи:

Document → Chunk (chunking: разбиение на фрагменты)

Chunk → ChromaVector (indexing: создание эмбеддингов)

Storage	SQLite	Хранение чанков и метаданных
Logger	structlog	Структурированное логирование
Package Manager	uv	Быстрый менеджер пакетов Python


### Инструкция по созданию AI-репетитора
1. Сбор данных
* Определить источники (документация, учебники, статьи)

* Реализовать краулер с фильтрацией по домену (Scrapy)

* Извлечь чистый текст (Trafilatura)

* Сохранить в JSON (documents.json)

Пример:

bash
uv run python crawl.py

2. Обработка и индексация
* Разбить документы на чанки (850 символов, overlap 140)

* Сохранить чанки в SQLite (documents.db)

* Создать эмбеддинги (rubert-tiny2, 384-dim)

* Индексировать в ChromaDB (chroma_db/)

Пример:

bash
uv run python embeddings.py

3. RAG Pipeline
* Поиск: векторный поиск по косинусной близости (ChromaDB)

* Rerank: LLM-переранжирование (Gemma 27B)

* Расширение контекста: добавление соседних чанков

* Генерация: промпт с контекстом → LLM → ответ

Реализация:

Класс RAG в services/rag.py

Методы: search(), rerank(), generate()

4. Модерация
* Фильтрация входа: блокировка нецензурного контента (500+ слов)

* Маскировка PII: email, телефоны, банковские карты

* Фильтрация выхода: удаление опасного кода, SQL injection

Реализация:

Класс ContentModerator в services/moderator.py

Методы: filter_input(), mask_pii(), filter_output()

5. UI
* Чат-интерфейс с историей сообщений

* Отображение источников с кликабельными ссылками

* Генерация тестов для самопроверки (Tab 2)

* Выбор LLM провайдера (Gemini / Qwen) в боковой панели

### Запуск:

bash
uv run streamlit run app.py
6. Выбор LLM провайдера
* Gemini (по умолчанию)
Требования: API ключ (GEMINI_API_KEY)

Плюсы: быстрый, высокое качество

Минусы: отправляет данные в облако Google

* Qwen (опционально)
Требования: Ollama установлен локально

Плюсы: 100% приватность, без API-лимитов

Минусы: требует ~8 ГБ RAM для 7B модели

*Установка Qwen:*

bash
ollama pull qwen2.5:7b
ollama serve
Переключение в UI:

Боковая панель → "⚙️ Выбор LLM" → выбрать qwen → выбрать модель

### Масштабируемость
* Новые предметы
Добавить URL в SEED_URLS (в core/config.py), перезапустить краулер:

python
SEED_URLS = [
    "https://cloud.ru/docs",
    "https://new-source.com/docs",  # новый источник
]
* Другие базы знаний
Реализовать новый loader в Storage:

* Другие LLM
Изменить провайдер в core/config.py:

python
LLM_DEFAULT_PROVIDER = LLM_PROVIDER_QWEN  # вместо Gemini
LLM_DEFAULT_MODEL = LLM_MODEL_QWEN
Или добавить новый провайдер:

python
LLM_PROVIDER_OPENAI = "openai"
LLM_MODEL_OPENAI = "gpt-4o"

### Этика и безопасность
1. Фильтрация контента
* Блокировка 500+ нецензурных слов на входе

* Предупреждение пользователя без генерации ответа

2. Защита персональных данных
* Маскировка PII

3. Защита от атак
* Prompt injection

4. Безопасность ключей
* API-ключи хранятся в .streamlit/secrets.toml (не коммитится в Git)

.gitignore содержит secrets.toml, .env, *.key
